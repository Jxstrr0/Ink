# Ink: build plan

A tattoo artist career game by Longlight Interactive. Start as an apprentice sweeping floors, learn on fake skin, build a client list, open a studio, and end with a two-year waiting list and a body of work that has aged on real people who keep walking back through your door. Every tattoo is a design decision, a hands-on session, a healed verdict, and a memory the game never forgets. Phone-first, free, hosted on GitHub Pages, listed on Kelbo.Website.

Hand this file to a Claude Code session, e.g.:

> Read `CLAUDE.md` (if it exists yet), then `docs/INK-PLAN.md`. Do PR 0 only. Merge it when it passes, then give me the phone test.

Commit this file as `docs/INK-PLAN.md` in the `Ink` repo so every session can find it. Tick off PRs in the checklist at the bottom. Defaults Kelbo has not yet confirmed are marked **(default, see Q#)**; ask before the PR they affect.

## 0. Ground rules

- **Stack is PEW's stack, lifted directly.** Reference repo: `github.com/Jxstrr0/350Chev` (read its `CLAUDE.md` and `src/README.md`; copy `build.js` and the shape of `check-savecode.js`). Plain HTML, CSS and classic (non-module) JavaScript. No package.json, no npm, no bundler, no CI. three.js r128 from CDN (same on-demand `PEW_LIBS` pattern). Google Fonts only.
- **Edit `src/` only.** `index.html` and `sw.js` are generated by `node build.js` from `src/manifest.txt`. Run `node build.js`, `node build.js --check`, `node check-savecode.js` before every commit, and from PR 1 on also `node tools/sim-test.js`. Commit `src/`, `index.html`, `sw.js` together.
- **One `claude/...` branch + PR per section. When the PR's checks pass (the commands above run clean and the phone-test items you can verify in code are done), merge it into `main` yourself** with a merge commit titled `x.y.z.w: summary`. GitHub Pages deploys `main` automatically, so merging is the deploy; don't wait for Kelbo to merge. Then post the phone test.
- Bump the **third** VERSION number (`src/app/state.js`) per PR; fourth for hotfixes.
- **Three graphics tiers** (`lite`, `full`, `ultra`, `src/app/perf.js`). Lite is the phone default and must keep working after every change.
- **Three namespaces:** `INK_SIM` (design scoring, aging model, client logic, calendar, economy; never touches DOM or three.js; runs in plain node), `INK_VIS` (three.js body and studio; draws what the sim says), app glue in `src/app/`.
- **All randomness goes through `INK_SIM.rng`** (`src/sim/rng.js`, seeded, mulberry32 or similar). No bare `Math.random()` in `src/sim/`. Node tests run on a fixed seed so numbers are repeatable.
- **Tuning numbers live in tables, not inline.** Every table is named in this plan.
- **The state object `S` is defined once** (PR 1, section 4e). Later PRs add fields to that definition; they do not invent them inline.
- localStorage wrapped in try/catch. Keys: `ink-save`, `ink-slot1` to `ink-slot3`. A new key must be added to `buMake`/`buWrite` in `savecode.js`; stop and ask before adding one.
- Save codes: `INK1:` + the keys as JSON, LZW-squeezed, base64url, + 6-char checksum. Tattoos save as design parameters + session outputs + date, **never as rasters**; everything visual is re-rendered from the sim. See PR 7 for the client-record cap.
- Respect `prefers-reduced-motion` and `prefers-reduced-transparency`. Light theme gets every change.
- Comments in plain English at the top of each file. Real design decisions get asked, not guessed. End each PR with a plain-language "what changed / how to test on a phone" summary.
- **Content rules (hard):** all clients are adults (the game states 18+ at the consult and never generates a minor). The body model is a neutral, stylized mannequin with no nudity; placements are limited to arms, legs, back, chest (upper), ribs/side, shoulders, neck, hands and feet. No real people, no real brands, no hateful imagery; the element library is curated, never free text rendered as art.
- **Assets:** CC0 or CC-BY only, credited in `models/CREDITS.md`, `art/CREDITS.md`, `sounds/CREDITS.md` (name, author, licence, URL). Kelbo's own Blender work is noted as original. No NC or ND assets.

## 2. Direction

PEW's loop with the race replaced by a client: **Consult → Design → Stencil → Session → Heal → Years later.** The Whip's DNA on top: every client is a person who remembers you. The thing no other game does: **the canvas remembers.** The same arm you tattooed in 2003 is on the chair in 2019, and your old work is part of the brief.

What must feel great, in order:

1. **The heal reveal.** Two in-game weeks later, the bandage comes off and you see whether the lines held, with the stencil ghosted over the healed piece so you see exactly where it drifted. That is the verdict screen.
2. **The design board.** Composing a piece that reads at size, flows with the limb and fits the client, with deltas that tell you why.
3. **The body of work.** A gallery of everything you've done, shown as it looks today, aging in the background.
4. **Returning clients.** Someone you tattooed in year two walking in for a sleeve in year nine, and the reckonings where your apprentice-era work comes back aged.

Look: warm studio light, black ink on a cream board, hand-lettered signage. Longlight UI (Space Grotesk), a condensed display face for flash headers. Not neon; this is a working shop.

## 4. PR 1: Design sim and aging model (text only)

All in `src/sim/`. No DOM. Runs in node.

### 4a. Element library (`src/sim/elements.js`)

`ELEMENTS`: curated vector motifs as SVG path data with metadata. Each has `id`, `name`, `family` (motif | lettering | frame | fill | texture), `styles[]` it belongs to, `minSizeMm` (below this it will blur), `detail` (0..1), `lineWeightDefault`, `colourable`, `tags[]` (nature, animal, memorial, nautical, geometric, script…), `unlock` (`start` | `style:<id>:<level>` | `rnd:<id>`).

First pass: ~120 elements across styles, drawn as simple original SVG by Claude Code (geometric, botanical, lettering styles, frames) and extended later by Kelbo's own art or CC0 motif packs (credited). **Nothing traced from real tattoo artists' work.**

`STYLES`: traditional, neo-traditional, blackwork, fine-line, realism (stylized), japanese, lettering, geometric, watercolour. Each with `ageFactor` (how well it holds), `demandCurve` by year, `clientSegments`.

`PLACEMENTS`: every allowed zone (including left and right ribs/side, the highest-pain zone in the table, with a curved flow field that follows the ribcage) with a flow vector field, a base wrap width, pain level, visibility, sun exposure and the UV island it lives on (PR 6). `BODY_SHAPES` (three) scale the wrap width per zone, so a sleeve on a bigger arm has more room.

### 4b. Design scoring (`src/sim/design.js`)

A design is `{placement, sizeMm, elements:[{id, x, y, scale, rot, lineWeight, fill, colour}], style}`.

`scoreDesign(design, client, skills)` returns:

- `readability`: penalises elements under `minSizeMm` at their scaled size, too-dense detail, thin lines in small spaces, and low contrast for the client's skin tone (`SKIN_CONTRAST` table: light colours and fine detail read less on darker skin; bold black reads everywhere).
- `flow`: fit to the placement template's flow lines and wrap width (after the body-shape scale); pieces that fight the limb score low.
- `balance`: visual weight distribution across the composition.
- `coherence`: elements from mixed styles penalised unless the style is explicitly a blend the player has unlocked.
- `fit`: match to the client's hidden wants (style, size, tags, colour) and stated must-haves.
- `agePrediction`: from `aging.js` at 5/10/20 years.
- `hours`, `sessions` (by size and detail), `price` (by hours × rate × reputation × `PRICE_INDEX` for the year).
- **Stress report** from `COMBOS`: "script at 9 mm: letters will close up within 5 years", "watercolour on the hand: fades hard, client works outdoors", "two styles fighting: traditional bold lines next to fine-line stippling", "piece crosses the elbow crease: distorts when bent", "pale yellow on this skin tone: won't read at all".

### 4c. Aging model (`src/sim/aging.js`)

`age(tattoo, years)` returns `{blur, fade, spread}`. Inputs: line weight, depth quality from the session, detail density, colour palette (`COLOUR_FADE` table: lights fade fastest), placement (`PLACEMENT_WEAR`: hands, feet and sun-exposed areas wear more), style `ageFactor`, ink quality from the kit (`INKS`), client's skin tone and sun exposure trait, and years. Output drives the render (blur radius, saturation, edge spread) and the "how it looks today" score.

### 4d. Node tests

`tools/sim-test.js`: on a fixed seed, scores ~15 `TEST_DESIGNS` against ~5 `TEST_CLIENTS`, prints every sub-score and the aging at 5/10/20 years. Put before/after numbers in commit messages when scoring changes. This runs before every commit from here on.

### 4e. State shape (`src/app/state.js`)

Define `S` in full now, even where later PRs fill it in: `week`, `year`, `cash`, `rate`, `rep{walkins,collectors,peers}`, `skills{}` (section 10), `kit{}` (PR 4), `clients[]`, `pieces[]`, `queue[]` (booked sessions), `studio{stage,staff[]}`, `goals{}`, `settings{}`, `seed`. Add the `S` map to `src/README.md`. A later PR that needs a new field adds it here and to the README in the same commit.

**Phone test:** none visual; the Design tab shows the raw score object.

## 5. PR 2: Design board (Design tab)

- **Body diagram:** an original front/back SVG drawn in this PR (`src/app/design.js` inline or `art/body-flat.svg`), stylized to match the mannequin. Tappable zones from `PLACEMENTS`; each zone shows its wrap width (for the current body shape), pain level and visibility.
- **Board:** a cream canvas (both themes, Q10) with the placement template's silhouette and flow lines faintly behind. Elements are added from a drawer (filtered by style, family, tag, unlocked), then pinch-scaled, rotated and dragged. Snap-to-flow toggle. Line weight and fill per element. Colour palette by style, with swatches greyed when `SKIN_CONTRAST` says they won't read on this client.
- **Live deltas** (PEW's `.d` lines) on the docked capsule: readability, flow, fit, hours, sessions, price, and the aging prediction as a small 0/10/20-year strip.
- **Stress report** panel.
- **Flash wall:** pre-composed designs (`FLASH` table) usable at a discount in hours; your own saved designs become your flash over time.
- Undo/redo. Designs save with the client's record.

**Phone test:** compose a forearm piece on Lite from three elements, watch readability drop when you shrink lettering, fix it, save it; light theme reads.

## 6. PR 3: Clients, the consult, and the week

`src/sim/clients.js`, `src/sim/calendar.js`, `src/sim/market.js`, `src/app/clients.js`.

### 6a. The week clock (`src/sim/calendar.js`)

- `INK_SIM.advanceWeek(S)` is the only thing that moves time. In order: heals tick (PR 5), aging recomputes for pieces that crossed a year boundary, bookings for the week are generated by `market.js`, rent/supplies/staff are charged (PR 7), queued events fire (PR 8), the trend wave updates (PR 8).
- `WEEK` config: chair-hours per week (`hoursPerWeek` by act), max bookings, walk-in slots. A session that doesn't fit the week's hours continues next week.
- **Skip forward:** a "Next" button on the Career tab advances to the next booked client, heal, or event, never more than 4 weeks at a time, with a one-line log of what happened. Without this, 1,560 weeks is a grind.

### 6b. Market (`src/sim/market.js`)

- `generateWalkins(S)`: how many arrive and what they want, from the current year's trend wave (PR 8), the studio's storefront vibe (PR 7), reputation tracks and the week config. Booked clients come from returns and referrals (6d), not here.
- `PRICE_INDEX`: per-year multiplier so a 2003 forearm piece and a 2027 one price like their era. Rent, supplies and rates all use it.

### 6c. Client generation and consult

- **Client generation:** persistent records with name, pronouns, age (18+), body shape, skin tone, job (affects visibility needs), traits (`CLIENT_TRAITS`: pain tolerance, sun exposure, aftercare, budget, loyalty, talkative, trusting), style wants, hidden must-haves and dealbreakers, an opening brief written from templates (`BRIEFS`: "something for my grandmother, she loved gardens, nothing too girly, left forearm"). All from `INK_SIM.rng`.
- **Consult:** a short branching chat (3–5 exchanges) built from `CONSULT_QUESTIONS`. Questions reveal hidden wants; the consult skill widens what you learn. Options include talking a client out of a bad idea (lettering too small, a portrait on the hand), which costs the booking sometimes and earns loyalty other times. The consult ends with price and deposit; the client can walk.

### 6d. Memory and returns

- **Memory:** each client keeps a ledger (`history[]`) of consults, pieces, heals, reviews and how you treated them. Loyalty drives returns, referrals and reviews (`REVIEWS` table: text templates by heal grade and loyalty). Referred clients arrive with a reference to who sent them.
- **Returns:** scheduled from `RETURN_RULES`: add-ons, sleeves around an existing piece, cover-ups of someone else's work (a dark blob to design around; pure puzzle), cover-ups of your own early work, touch-ups. A return brief always references the existing piece by name and year.
- Clients tab: list, filters, each client's pieces as they look today.

**Phone test:** run three consults, discover a hidden dealbreaker by asking, talk one client out of tiny script, advance a week with Next, see a referral arrive.

## 7. PR 4: The session and the kit

`src/sim/session.js`, `src/sim/kit.js`, `src/app/session.js`.

### 7a. The kit (default, Q9)

`KIT` tables, bought with cash, shown on the Studio tab as a small build panel with PEW-style deltas:

- `MACHINES`: coil, rotary, wireless pen; each with a band width, a trauma factor and a buzz profile for the synth.
- `NEEDLES`: liner groupings (3RL, 5RL, 7RL…) and mags; grouping sets the line weight you can actually lay and how fast shading fills.
- `INKS`: brand-less tiers; affect saturation and the `aging.js` fade rate.
- `VOLTAGE` / stroke as two sliders: higher is faster but raises trauma and narrows the pace band.

The kit is read by the session for its bands and by `aging.js` for ink quality. Nothing else in the game depends on it, so if Q9 says no, drop this subsection and keep `MACHINES` as a single unlock track.

### 7b. The session

- **Stencil placement:** position the design on the flat body diagram (3D in PR 6); the sim checks flow and crease crossing again.
- **Handedness and assist** (from this PR, not PR 9): a left/right setting mirrors the meter layout; an **Assist** setting widens the pace band and slows the marker for players who can't trace precisely. Both in `S.settings` and the Settings pane.
- **Linework phase (default, Q4):** the stencil path is shown; a pacing marker travels it. The player traces with a finger (or mouse on desktop). Score per segment = accuracy to the path × pace consistency (within a band, shown as a steady-hand meter). Rushing blows out lines (`blowout`), stopping and restarting leaves joins. Skill and the kit widen the band.
- **Shading phase:** hold-and-sweep over shaded zones; a saturation meter fills; overworking a zone raises `trauma`.
- **Colour packing phase:** short back-and-forth swipes per colour zone; same meter. Meters use shape as well as colour so they read for colour-blind players.
- **Client meters:** `pain` (by placement, their tolerance, your technique) and `fatigue`; breaks reset some; numbing cream (a consumable cost) lowers pain; chatting (if talkative) slows fatigue. Hitting the limit ends the session early and the piece continues next week.
- **Multi-session pieces:** large designs split into sessions by `hours`; progress persists in `S.queue`.
- Output: `depthQuality`, `lineQuality`, `saturation`, `trauma`, `sessionsUsed`, which feed healing and aging.
- Tick sound from `sound/synth.js`: a machine buzz whose pitch follows pace and whose timbre follows the machine; clean segments sound smooth, rushed ones stutter.
- Reduced motion: pacing marker becomes a static highlight; Lite: 30 fps canvas.

**Phone test:** tattoo a small flash piece on Lite in one session; feel the difference between a steady trace and a rushed one; a ribs placement runs the pain meter up faster than a forearm; switch to a 7RL and see the line-weight band move.

## 8. PR 5: Heal, reveal, body of work

- **Healing:** two in-game weeks, ticked by `advanceWeek`. Result from session outputs plus client aftercare trait: crisp / slightly soft / patchy / blown out / infected (rare, needs high `trauma` and bad aftercare). Infection is the engine-gone moment: free fix, reputation hit, an apology scene. The heal grade maps to aging inputs through `HEAL_GRADES` (a patchy heal starts with spread already applied).
- **Reveal screen:** before/after with the healed render (aging model at 0 years), the stencil ghosted over it as a faint overlay (PEW's ghost-curve idea) so drift and blowouts are visible, the client's reaction line, a review chance, and a "portfolio?" prompt. The verdict uses PEW's analysis-screen pattern.
- **Body of work:** a gallery of every piece, rendered as it looks *today* via `aging.js`, filterable by year, style, client. Renders are cached per piece and only recomputed when its age crosses a year or the piece changes. Tapping a piece shows its history and the client's ledger.
- **Reputation tracks (`REP_TRACKS`):** walk-ins (speed, price), collectors (custom work, style), peers (clean heals, conventions). Each unlocks client segments and events.

**Phone test:** heal a piece, get a review, open the body of work a year later and see the aging strip changed.

## 9. PR 6: 3D body and studio (Studio tab)

`src/vis/`, three.js r128, Lite first.

- **Mannequin (`vis/body.js`):** one low-poly adult mesh with body-shape morph targets (three shapes) and a skin-tone material. Clothed (shorts and crop top baked into the mesh, the ribs/side left bare). **UV layout rule: one island per limb or zone** (left arm, right arm, left leg, right leg, back, upper chest, left side, right side, neck, each hand and foot). Morphs keep UVs, so decals survive a shape change.
- **Decals (`vis/decals.js`):** each tattoo rendered to an offscreen canvas in its island's UV space and composited into a per-client skin texture; aging applies blur and fade on the canvas. One texture per visible client, updated only on change. Lite: 1024² texture, Full: 2048². A sleeve is several pieces, one per island, that the sim links as one `set` so the gallery and brief treat it as one work; the vis never draws across islands.
- **Studio (`vis/studio.js`):** the shop interior at its current stage (PR 7), the chair, your station. The client sits for consult and session. Camera presets: consult (face-on), stencil (the limb), session (close on the work), reveal.
- `INK_VIS.setClient(c)`, `.setTattoos(list)`, `.setView(name)`, `.setStudio(stage)`, `.fps()`.
- Stencil placement moves from the flat diagram to the 3D limb: drag on the surface, rotate; the sim recomputes flow and crease crossing.

**Phone test (Lite):** a client sits, you place a stencil on a forearm in 3D, tattoo it, and the healed piece shows on the model; change the client's body shape and the piece stays put; fps steady, no auto-adjust toast.

## 10. PR 7: Career, studio build-out, money, staff, saves

`src/app/career.js`, tables in `src/app/state.js`.

- **Act 1 Apprentice (years 1–3):** a mentor (`MENTOR` character with opinions), chores that advance weeks, fake-skin practice (session mechanic with no client), flash drawing (board with constraints), then free pieces on friends, then paying flash walk-ins. Leaving early costs the mentor's goodwill, which matters later. **This act is the tutorial**; PR 9 only adds help overlays on top of it.
- **Act 2 Chair (years 3–8):** rent a chair (`CHAIR_SPLIT` percentage), build a client list, custom work unlocks, first convention, guest spots in other cities (travel cost, new client pool).
- **Act 3 Studio (years 8–20):** lease a space; build-out `STUDIO_STAGES` (stations, waiting area, flash wall, sterilization room, lighting, storefront vibe that sets walk-in mix). Hire artists (`STAFF`: own style, skill, ego, chair cut, poach risk), bookings, deposits, no-shows, supplies, rent, health inspections.
- **Staff pieces (default, Q11):** staff tattoo their own bookings without the minigame. `simStaffSession(staff, design)` produces session outputs from their skill and the shop's kit, with the same heal and aging rules. Their pieces count toward the **shop's** reputation and walk-in flow and appear in a separate Shop gallery; your own body of work stays yours. A staff infection hits the shop, not you.
- **Act 4 Legacy (years 20–30):** waiting list management, apprentices (who become staff or rivals), your own convention, a flash book, a product line, a TV offer (money vs credibility, Q7).
- **Signature style (`SIGNATURE`):** the sim tracks which styles, elements and placements you actually do most. Past a threshold, clients start asking for "your thing" in briefs, collectors weight it, conventions judge you against it, and rivals copy your flash (PR 8). No authored content; it falls out of play.
- **Apprentice lineage:** an apprentice you train inherits a blend of your `SIGNATURE` and their own leaning; their first solo piece lands on a client you share. If they leave to open a shop it carries your style into the rival pool.
- **Skills (`SKILLS`):** per style (levels unlock elements and widen session bands), plus consult, linework, shading, colour, speed. XP curves in `SKILL_XP`.
- **Money:** hourly rate (`RATE_BY_REP` × `PRICE_INDEX`), deposits, flash sales, merch, conventions. Spending: kit, supplies, studio, staff, travel, marketing. **Soft fail (default, Q12):** cash below `BROKE_FLOOR` for 4 weeks closes the studio, lets staff go and drops you to a rented chair; clients, pieces and rep survive.
- **Legacy screen:** at year 30, or from the Career tab any time after Act 3, a full-screen summary: oldest piece that still reads (by today's readability), client with the most pieces, pieces per decade, best heal, conventions won, apprentices and where they ended up. Shareable as a card (PR 9). The save stays playable afterwards.
- **Save size:** `S.clients` keeps full records for the `CLIENT_CAP` most recent or most loyal clients (default 200) and compacts the rest to `{name, pieces[], loyalty, lastSeen}`; compacted clients can still return. Pieces are never dropped. Check the save code stays under ~8 KB at year 30 in `tools/sim-test.js` with a synthetic 30-year run.
- Save/Restore with `INK1:` codes, three slots.

**Phone test:** play the apprenticeship on Lite through the first paying walk-in; rent a chair; hire an artist in Act 3 and see their piece in the Shop gallery but not yours; go broke on purpose and land back on a chair; back up and restore.

## 11. PR 8: Events, trends, rivals, social

- **Conventions (`CONVENTIONS`):** fresh-work and healed-work competitions judged on design score and heal quality; booth sales; meet collectors; see rivals' work.
- **Trend waves (`TREND_WAVES`):** per-year demand multipliers per style (fine-line boom mid-2010s, watercolour spike then fade, traditional evergreen). Clients' wants follow the waves through `market.js`.
- **Social media (from 2016, confirmed Q2):** a post action per healed piece; reach scales with design score, heal quality and follower count; followers convert to bookings from far away; one viral piece a career is a scripted possibility. Bad heals posted by clients hurt.
- **Rivals (`RIVALS`):** named shops that open nearby, poach staff, undercut prices, and copy your flash once you have a `SIGNATURE`; they remember.
- **Reckonings (`RECKONINGS`):** a few scheduled returns that are beats, not just bookings. A client from your first year walks in at year 12–18 with your apprentice-era piece aged in front of you; you can rework it free, cover it, or leave it. A client who bad-mouthed a patchy heal comes back once you're known. A mentor's referral in Act 3. Each fires once per career.
- **Health inspection:** checks sterilization and supplies; a fail closes the shop for weeks.
- **Cover-up puzzles:** arrive as events with a pre-placed dark decal to design around.
- **Goals (`GOALS`):** first clean heal, first custom piece, first return client, first convention award, open the studio, hire an artist, a client with 5+ of your pieces, survive a rival, a 20-year-old piece that still reads, an apprentice who opens a shop.

**Phone test:** advance two years, enter a convention, post a piece, watch a trend shift change walk-in requests, hit the first reckoning.
